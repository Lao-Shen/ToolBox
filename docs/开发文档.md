# ToolBox（wails3 工具平台）项目地图

Windows 工具平台：主窗口（分组+工具卡片）+ 独立工具窗口 + 全局热键 + 系统托盘。
Wails v3.0.0-alpha2.122 + React（Vite）+ Go，仅 Windows。

## 常用命令

- 后端构建/检查：`go build . && go vet .`
- 重新生成前端绑定（改了 service 导出方法后必做）：`wails3 generate bindings`
- 前端构建：`cd frontend && npm run build`
- 开发运行：`wails3 dev`

### 外部依赖注意

- **图标提取复用 Forge 项目的 peicon**（`earwind.top/forge/peicon`，go.mod 里 `replace => ../Forge`）：
  纯 Go PE 资源解析，`List`/`ExtractSize`/`ExtractAll` 三个接口。勿自造 Win32 ExtractIconEx 方案。
  改 Forge 代码会影响 ToolBox 构建，两边需一起验证。

## 关键约定

### 新增工具的做法（热键与启动分发，2026-08-26 定）

热键分发层是通用的，**永远不改**：`HotkeyService` 只按 action 查注册表执行，
注册集中在一处 —— [service/hotkey.go](../service/hotkey.go) 的 `ConfigureHotkeyActions`。

- **常规工具（有界面的）标准做法**，照开机自启管理抄：嵌入 `WindowToggle`（见
  [service/window_toggle.go](../service/window_toggle.go)），提供 `OpenX`（点卡片：开着→聚焦）
  和 `ToggleX`（热键：开/关切换，避免重复启动）两个方法，再注册一行
  `registerAction("xxx", func(string) { svc.ToggleX() })`。用户点 X 关闭由
  WindowClosing 钩子自动清引用。
- **特例：截图类瞬态工具**（无窗口，"再触发 = 取消"）：取消语义由该服务自己实现
  （样板见 [service/screenshot.go](../service/screenshot.go) 的 capturing 重入分支 →
  [core/region_select.go](../core/region_select.go) 的 CancelOverlay），注册仍是一行。

前端侧：卡片点击按 `action` 分发（App.tsx handleToolClick），新工具在此加分支。

### 线程与 API 约束（踩过的坑，勿回退）

- **WM_HOTKEY 只投递到调用 RegisterHotKey 的线程**：注册/注销必须由热键专用线程执行
  （SetBindings 存 pending → PostThreadMessage 唤醒线程 applyBindings）。
- **wails 服务方法在主线程执行**：蒙层消息循环必须跑独立 OS 线程，否则与 wails 定时事件
  嵌套派发导致 WebView2 Eval 阻塞卡死。
- **wails3 此版本没有** `Window.Destroy()` / WindowDestroyed 事件 / `RegisterHotKey` 封装；
  关窗用 `Close()`（emit WindowClosing，InvokeSync 线程安全），`Show()` 对已销毁窗口自动重建；
  `NewWithOptions` 任意 goroutine 可调。
- **绑定生成器**：service 导出方法的参数/返回不能是另一服务类型（会被当模型导出导致 TS 重名），
  注入用接口（如 `ToolActionRunner func`）或非导出方法。
- lxn/win 缺的 API：RegisterHotKey、Rectangle_、DrawTextEx、ExtCreatePen、CreateBrushIndirect、
  FillRect 等，均查证后 syscall 直调或用已有等价物。

### 持久化文件（%APPDATA%\ToolBox\）

- `settings.json` 设置、`shortcuts.json` 快捷键、`startup_items.json` 自启关闭项记忆、
  `update.json` 更新模块设置（`auto_update`）、`icons/` 工具图标（前端经 `/icons/` 资产路由访问）

> 坑：`HotkeyService.SetBindings` 是「全量同步」——后端每次都会把当前绑定写回
> `shortcuts.json`（空表也写）。前端启动时**必须先等 `GetShortcuts` 回填完成再首次
> 同步**（见 App.tsx `shortcutsLoaded` 守卫），否则挂载时的空绑定会清空已存快捷键。

### 自动更新（自研更新链路）

- **验签**：[update.go](../update.go) 内嵌 [updater.pub](../updater.pub) 公钥，`verifyUpdateSignature`
  校验 ed25519 签名（签名对象是构件的 sha256 摘要，不是文件本身）。
- **链路**：[updateservice.go](../updateservice.go) 的 `UpdateService`：
  `CheckUpdate`（清单 30s 超时，204 无更新 / 200 解裸 JSON）→ `StartDownload`（10 分钟超时）→
  流式 sha256 + 验签 → 落 `%CACHE%\ToolBox\updates\<version>\` → `ApplyUpdate`
  写批处理等本进程退出后覆盖 exe 并启动新版。
- **更新策略**：`auto_update` 开启时启动 4s 后静默检查并**自动下载**，下载完发 `app:update:ready`，
  前端弹 notes，用户确认后重启；关闭时只在手动点「检查更新」后弹 notes，用户确认后下载安装。
  `dev` 构建跳过自动检查。
- **事件**：`app:update:progress`（下载进度）、`app:update:ready`（待确认）。
- **设置**：[settings_update.go](../settings_update.go) 存 `%APPDATA%\ToolBox\update.json`（`auto_update`，默认开）。
- **版本号**：构建时经 `PM_VERSION` 环境变量以 `-ldflags -X main.currentVersion=` 注入
  （见 [build/windows/Taskfile.yml](../build/windows/Taskfile.yml)）；未注入为 `dev`。
- **发布**：[project.json](../project.json) 配 `binary: bin/ToolBox.exe`，由桌面端「项目管理」发布时**直传单文件 exe**
  （带平台/摘要/sha256/ed25519 签名），供自更新。
- **前端**：设置弹窗「通用」自动更新开关；「关于」显示后端版本号 + 检查更新 / 下载并安装 / 重启并安装。
